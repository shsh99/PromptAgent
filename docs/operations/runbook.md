# 운영 런북

## 목적

장애 감지부터 완화, 복구, 회고까지 공통 절차를 제공한다.

## 적용 범위

API, 프론트엔드, DB, AI 모델, 웹 검색, CI/CD 장애에 적용한다.

## 함께 갱신할 문서

- [배포 구조](../architecture/deployment.md)
- [데이터 흐름](../architecture/data-flow.md)
- [Jenkins](jenkins.md)

## 초기 대응

1. 사용자 영향, 시작 시각, 환경, 최근 배포와 `traceId`를 확인한다.
2. 비밀값과 원문 입력을 제외한 로그·메트릭으로 범위를 좁힌다.
3. 데이터 손실·보안 사고 가능성이 있으면 쓰기 또는 외부 연동을 우선 차단한다.
4. 상태 페이지와 담당 채널에 사실, 영향, 다음 갱신 시각을 공유한다.

## 구성요소별 완화

- AI 장애: 시간 제한과 회로 차단기를 확인하고 규칙 폴백 또는 생성 기능 제한 모드로 전환한다.
- 웹 검색 장애: TTL 캐시와 내부 RAG만 사용하며 최신성 저하를 사용자에게 표시한다.
- DB 장애: 연결 풀·저장 용량·복제를 확인하고 쓰기를 제한한다. 임의 마이그레이션 롤백은 금지한다.
- 배포 장애: 스모크 테스트를 중단하고 이전 커밋 SHA 이미지로 트래픽을 복귀한다.
- CI 장애: 최초 실패를 로컬 재현하고 간헐 실패는 이슈·소유자·기한과 함께 격리한다.

복구 후 데이터 정합성과 핵심 사용자 흐름을 검증한다. 회고에는 원인, 탐지 지연, 영향, 타임라인, 교정 작업과 소유자를 기록하며 관련 아키텍처·운영 문서를 갱신한다.
