# 프롬프트 마켓

## 목적

업무별 검증 템플릿을 빠르게 발견하고 안전하게 복사하는 제품 계약을 정의한다.

## 적용 범위

마켓 탐색, 템플릿 상세·버전, 복사 이벤트와 게시 관리에 적용한다.

## 사용자 흐름

사용자는 카테고리·검색어·난이도로 템플릿을 찾고 카드에서 목적, 태그, 난이도, 검증 상태를 확인한다. 상세 작업대에서 공통 계약의 9개 필수 항목을 검토한 뒤 서버가 조립한 완성 프롬프트를 복사한다. 상세 생성기로 확장하는 연결은 후속 기능에서 제공한다.

초기 카테고리는 업무 메일, 유튜브 기획·편집, 웹사이트 개발, 코드 오류 분석·수정, 보고서, 이미지 생성, 데이터 분석, 회의·기획이다.

## 공개·검색 계약

- 목록: `GET /api/v1/prompt-templates`
- 상세: `GET /api/v1/prompt-templates/{templateId}`
- 목록 필터: `category`, `difficulty`, `query`, `page`(기본 0), `size`(기본 20, 최대 100)
- 검색어는 NFKC 정규화, 대소문자·연속 공백 정규화 후 토큰을 모두 포함하는 항목만 반환한다.
- 검색 대상은 제목, 요약, 카테고리 표시명, 태그다. 프롬프트 본문은 검색하지 않는다.
- 존재하지 않거나 공개 대상이 아닌 상세 ID는 모두 같은 `TEMPLATE_NOT_FOUND` 문제 상세 404로 응답한다.

프론트엔드는 필터와 페이지를 URL query에 기록하고 뒤로가기·앞으로가기를 복원한다. 목록·상세 응답은 런타임에서 필수 필드와 알 수 없는 필드를 검사하며, 서버의 공개 판정을 다시 추측하지 않는다.

## 데이터와 상태

템플릿은 식별자, 버전, 카테고리·태그, 난이도, 검증 결과와 공통 프롬프트 계약을 가진다. 수명 주기 상태는 `DRAFT`, `REVIEWED`, `PUBLISHED`, `ARCHIVED`, 검증 상태는 `PENDING`, `VERIFIED`, `REJECTED`다. 현재 공개 조건은 `PUBLISHED`이면서 `VERIFIED`이며 application 계층에서 저장소 결과를 다시 검사한다.

초기 단계는 application 포트 뒤의 메모리 저장소와 6개 공개 fixture를 사용한다. PostgreSQL 영속화로 전환해도 HTTP 계약과 공개 조건은 유지한다. 템플릿 수정 시 기존 버전을 덮어쓰지 않고 새 버전을 만드는 정책은 영속화 단계에서 적용한다.

현재 복사는 브라우저 Clipboard API로만 수행하며 원문과 복사 이벤트를 서버에 저장하지 않는다. 추후 복사 이벤트를 도입하면 템플릿·버전·시각만 기록하고 사용자 원문은 저장하지 않는다. 리뷰와 게시 권한은 분리하고 철회된 템플릿의 기존 사용 이력을 보존한다.
