# 인텐트 추출과 RAG

## 목적

사용자 업무 이해, 내부 지식 검색, 최신 웹 정보 결합 규칙을 정의한다.

## 적용 범위

상세 생성기와 에이전트 추천기의 인텐트·검색·프롬프트 조립에 적용한다.

## 하이브리드 인텐트

키워드·패턴 규칙으로 빠른 1차 결과를 만들고 모호하거나 복합적인 입력은 LLM 구조화 추출을 수행한다. 결과는 intent, confidence, task, targetAudience, constraints, outputFormat, keywords, retrievalRequired를 가진다. 허용 인텐트, 신뢰도, 문자열 길이, 배열 크기를 서버에서 검증한다. 낮은 신뢰도는 확인 질문을 하고 파싱·검증 실패는 규칙 결과로 폴백한다.

## 내부 RAG

승인된 템플릿, 작성 가이드, 품질 기준, 모델 규칙, 제품 문서를 의미 단위로 청크화한다. 출처, 문서 버전, 언어, 접근 범위, 체크섬과 임베딩을 저장한다. pgvector cosine 의미 검색과 PostgreSQL 전문 검색을 병합하고 중복 제거 후 임계값을 넘는 상위 4~6개만 사용한다. 초기 벡터 인덱스는 HNSW다.

## 웹 검색 구현 계약

최신 외부 정보가 필요할 때만 교체 가능한 게이트웨이로 검색한다. 검색 요청은 서버 정책에 등록된 허용 도메인과 사용 사례별 도메인 allowlist의 교집합으로 제한한다. 도메인은 IDNA 변환과 소문자 정규화 후 비교하며 와일드카드는 명시적으로 승인된 하위 도메인에만 사용한다. 대상 사이트의 `robots.txt`, 인증·구독·접근 제한과 서비스 약관을 준수하고 우회하지 않는다.

외부 URL을 조회하는 모든 경로는 다음 SSRF 방어를 공통 클라이언트에서 강제한다.

- URL scheme allowlist는 기본 `https`이며 승인된 연동에만 `http`를 별도로 허용한다. 사용자 정보가 포함된 URL과 그 밖의 scheme은 거부한다.
- 최초 요청 전에 호스트를 DNS/IP로 해석하고 IPv4·IPv6의 loopback, link-local, private, multicast, unspecified 대역과 cloud metadata 주소를 차단한다.
- 모든 redirect는 횟수를 제한하고 새 URL의 scheme, 도메인, DNS/IP를 다시 검증한다. DNS rebinding을 막기 위해 실제 연결 대상 IP도 검증 결과와 일치시킨다.
- 검색어와 URL 입력 크기는 각각 UTF-8 2 KiB, URL 수는 요청당 10개로 제한한다.
- 응답 MIME allowlist는 `text/html`, `text/plain`, `application/json`이며 선언 MIME과 실제 콘텐츠 형식이 다르면 거부한다.
- 압축 해제 후 응답 크기는 URL당 2 MiB로 제한하고 초과하면 즉시 스트림을 중단한다.
- 기본 시간 제한은 `connect timeout` 2초, `read timeout` 5초, 요청 전체 `total timeout` 10초다. 운영 환경은 더 짧게 조정할 수 있으나 무제한 값은 허용하지 않는다.

검색 결과는 제공자, 정규화 쿼리 해시, URL, 제목, 검색 시각, 사용 여부를 짧은 TTL 캐시에 저장한다. TTL은 기본 15분이며 최신성 요구에 따라 더 짧게 설정한다. 웹 본문과 임베딩을 내부 RAG나 다른 장기 저장소에 자동 축적하는 것은 금지한다. 감사 로그에는 정책 결정, 차단 사유, 지연, 응답 크기, 캐시 적중을 기록하되 API 키, 인증 헤더, 쿠키, 원문 쿼리와 개인정보 등 비밀은 제외한다.

## 프롬프트 조립

시스템 정책, 구조화 인텐트, 내부 RAG, 웹 출처, 템플릿, 사용자 입력, 출력 스키마, 최종 검증 지시 순으로 조립한다. 웹과 RAG 컨텍스트는 출처와 검색 시각이 있는 비신뢰 데이터로 감싼다. 컨텍스트 예산을 초과하면 낮은 점수부터 제거한다.
