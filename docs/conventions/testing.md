# 테스트 컨벤션

## 목적

변경 위험에 비례한 자동 검증과 TDD 작업 순서를 정의한다.

## 적용 범위

기능, 오류 수정, 리팩터링, 마이그레이션, 저장소 자동화에 적용한다.

## 함께 갱신할 문서

- [Java](java.md)
- [React·TypeScript](react-typescript.md)
- [GitHub Actions](../operations/github-actions.md)

## 원칙

행동을 설명하는 실패 테스트를 먼저 작성하고 의도한 이유로 실패함을 확인한다. 통과시키는 최소 구현 뒤 중복과 이름을 정리하며 전체 테스트를 다시 실행한다. 테스트는 구현 세부보다 공개 계약과 사용자 관찰 결과를 검증한다.

## 계층

- 단위: 도메인 규칙, 인텐트 검증, 프롬프트 계약, 순수 UI 로직
- 슬라이스: Spring MVC·JPA 경계와 React 컴포넌트 상호작용
- 통합: PostgreSQL/pgvector, Flyway, 외부 게이트웨이 어댑터
- 계약: OpenAPI, 프론트 생성 타입, 모듈 공개 DTO
- E2E: 마켓 복사, 상세 생성, 에이전트 패키지 다운로드 핵심 흐름

외부 AI와 검색은 결정적 fake로 오류·시간 초과·폴백을 검증하고, 실제 제공자 스모크 테스트는 비밀값이 있는 별도 환경에서 실행한다. flaky 테스트는 재시도로 숨기지 않고 격리 이슈, 소유자, 해소 기한을 기록한다.

PR 변경 문서에는 실행 명령, 성공·실패 수, 미실행 항목과 이유를 남긴다.
