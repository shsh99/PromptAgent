# Git 작업 흐름

## 목적

이슈에서 `dev` 병합까지 추적 가능한 작업 절차를 정의한다.

## 적용 범위

모든 코드, 문서, 운영 설정 변경에 적용한다.

## 함께 갱신할 문서

- [GitHub Actions](../operations/github-actions.md)
- [AI 리뷰](../operations/ai-review.md)
- [운영 런북](../operations/runbook.md)

## 브랜치

`main`은 운영 가능한 릴리스, `dev`는 통합 기준선이다. 작업 브랜치는 `feat/<이슈번호>-<slug>`, `fix/...`, `docs/...`, `chore/...` 형식을 사용한다. `codex/` 접두사는 금지한다.

## 절차

1. 목적·범위·완료 조건이 있는 한글 이슈를 생성한다.
2. 최신 `dev`에서 작업 브랜치를 만들고 하네스로 작업을 분배한다.
3. 테스트, 구현, 문서, `docs/changes/` 기록을 같은 작업에 포함한다.
4. `[기능]`, `[수정]`, `[문서]`, `[테스트]`, `[정리]`, `[배포]` 유형의 한글 커밋을 만든다.
5. `Closes #<이슈번호>`가 있는 한글 PR을 `dev` 대상으로 연다.
6. Actions, AI·사람 검토를 통과한 뒤 squash merge한다.
7. 이슈 종료를 확인하고 로컬 `dev`를 fast-forward로 최신화한다.

강제 push, 서명되지 않은 임의 바이너리, 비밀값 커밋을 금지한다. PR마다 변경 목적, 영향, 테스트, 배포, 위험·롤백, AI 사용을 기록한다.
